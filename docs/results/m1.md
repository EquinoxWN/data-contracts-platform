## Demo: the pull-request gate on a real git repository

A temporary repository publishes `contracts/orders.yaml` on `main`; the working copy is then edited
and checked with `datacontract check-pr --base main`.

Breaking edit (status `refunded` added, `coupon_code` renamed to `coupon`, freshness 1 h to 1 day):

```
contracts/orders.yaml: 4 change(s), 3 breaking
  BREAKING  orders                       freshness-loosened: 3600s -> 86400s
  BREAKING  orders.status                allowed-values-extended: new values ['refunded']
  BREAKING  orders.coupon_code           field-removed: consumers selecting it will fail
  safe      orders.coupon                field-added: new optional string
Breaking changes found: this pull request must not merge as is.
exit=1
```

Safe edit (freshness 1 h to 1 min):

```
contracts/orders.yaml: 1 change(s), 0 breaking
  safe      orders                       freshness-tightened: 3600s -> 60s
No breaking changes.
exit=0
```

## Quality control (DMAIC)

| Phase | This repository |
|---|---|
| Define | A renamed column, a new status value or a slower pipeline upstream silently breaks dashboards and models downstream, which hurts teams that consume shared datasets. M1 counts when producers can describe a dataset in a YAML contract, the CLI classifies every change as safe or breaking from the consumer's view, CI fails a pull request on any breaking change, and Python and JavaScript classify the shared cases identically ([RFC 0001](../rfc/0001-design.md)). |
| Measure | `make test`, ruff, `node --check`, `spec/build_cases.py --check` and `pip-audit` on an Intel Core i7-13700H with Windows 11, plus `check-pr` against a real temporary git repository. 58 Python and 26 JavaScript tests passed, 0 failed; all 25 hand-labelled cases got the same verdict in both languages; the breaking demo edit exited 1 and the safe edit exited 0. |
| Analyze | The classifier matched every label, 16 invalid contract shapes were rejected, and 5 option-like or malformed git refs were refused. No defects recorded. The first blocked pull request and the before/after incident count are not measured yet (M3). |
| Improve | No defect needed a change in M1; the 2026-10-06 recheck repeated every suite and audit with the same results. |
| Control | The `ci` workflow's `build` job runs `make ci` (cases up to date, ruff with security rules, format check, `node --check` and both test suites) and `make audit` (`pip-audit`); the `contracts` job runs `datacontract validate` and `check-pr` against the base branch on every pull request and fails on a breaking change. In the code, contracts load with the safe YAML loader, files over 1 MB are refused, git runs with fixed arguments and validated refs, and a missing base ref fails closed with exit code 2. |
