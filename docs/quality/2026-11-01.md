# Quality check against the 10 rules (2026-11-01)

Checked on Windows 11 with Python 3.14.5 (PyYAML 6.0.3) and Node.js 24.19.0. The only external
calls are `git show` and `git ls-tree` in `gitbase.py`; the only writes are the optional GitHub job
summary and `spec/build_cases.py`.

## Rules

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | fixed | `gitbase.py` ran git without a timeout, so a hung git (credential prompt, locked repo) hung the CI check. All git calls now go through `_git` with a 60 s timeout; `TimeoutExpired` and a missing git become `GitError`, which the CLI reports with exit 2. Test: `test_check_pr_reports_a_hung_git_as_an_error`. No swallowed errors (`grep -rnE "except Exception\|except:\|pass$" src` finds nothing). |
| 2 | Writes safe to retry | pass | `build_cases.py` rewrites `spec/cases.json` deterministically (`--check` proves it). The job summary is appended once per run, which is how `GITHUB_STEP_SUMMARY` is meant to be used. No other writes. |
| 3 | No race conditions | N/A | Single-process CLI, no threads or async code, no shared state. |
| 4 | Don't trust the clock | N/A | No timestamps or durations; freshness SLAs are compared as configured seconds only. |
| 5 | Read before changing | fixed | The code reads one env var, `GITHUB_STEP_SUMMARY`, which the README did not mention; it is now documented next to the exit codes. Every path in the README tables exists. |
| 6 | Never break compatibility | pass | The tool's job is this rule: 26 hand-labelled cases classify field removal, type narrowing, nullability, enum and SLA changes. CLI flags and exit codes are unchanged. |
| 7 | One source of truth | pass | `spec/cases.json` is generated from `contracts/orders.yaml` by `spec/build_cases.py` and checked for staleness in `make lint`; both classifiers read it. Version 0.1.0 agrees in `pyproject.toml`, `__init__.py` and `package.json`. |
| 8 | Small changes, no secrets, validate input | fixed | No secrets. Inputs are validated (`parse`, 1 MB file limit, safe YAML loader, git ref allowlist). Defect found: the Python classifier treated `true` and `1` as the same allowed value (`True == 1`), so replacing `[0, 1]` with `[false, true]` was reported as no change in Python but as breaking in JavaScript. `diff.py` now compares with a key that keeps booleans apart, and the case is in `spec/cases.json` so both languages are held to it. |
| 9 | Tests that can actually fail | fixed | No skipped or assertion-free tests. 25 hand mutations below: 3 of 22 original mutants survived and now have tests. |
| 10 | Re-verify | pass | `build_cases.py --check`, `ruff check`, `ruff format --check`, `npm run lint`: clean. `pytest`: `62 passed`. `npm test`: `tests 27`, `pass 27`, `fail 0`. `pip-audit`: `No known vulnerabilities found`. `audit_repo.py data-contracts-platform`: `OK`. |
